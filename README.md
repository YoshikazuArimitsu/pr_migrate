# pr_migrate — GitHub / Backlog Git の PR 双方向同期ツール

2 つのリポジトリ（a / b）のどちらかで作られた Pull Request を、もう片方に **ミラー PR** として作成し、
以降は両側の変更を同期し続けます。

- ミラー PR のタイトル先頭に **同期元リポジトリのラベル** が付きます（例: Backlog で作った PR は GitHub 側で `[BL] ログイン修正`）。
  ラベルが付いていない PR がそのリポジトリで作られた「元の PR」、付いている PR が「ミラー」です。
- **コメント**：どちらに書いても、もう片方へコピーされます（編集も反映）。
- **クローズ / マージ**：片方が閉じたら、もう片方も閉じます。再オープンも反映します。
- **ブランチ**：どちらかの head ブランチに push されたコミットを、もう片方へ反映します。
- **タイトル・本文**：同期元の変更をミラーへ反映します（ミラー側で編集しても同期元には戻りません）。

| 組み合わせ | ミラー作成 | コメント | インラインコメント | クローズ同期 |
|---|---|---|---|---|
| GitHub ⇄ GitHub | ○ | ○ | ○（同じ行に再現） | ○ |
| GitHub ⇄ Backlog | ○ | ○ | △（GitHub → Backlog はファイル名・行・差分付きの通常コメント） | GitHub 側 ○ / Backlog 側 △（※） |
| Backlog ⇄ Backlog | ○ | ○ | — | △（※） |

※ Backlog の API には PR をクローズする機能がありません。GitHub 側が閉じられたときは、Backlog の PR に
「手動でクローズしてください」というコメントを付け、ログと `list` に表示します。Backlog 側を閉じたときは GitHub 側を自動でクローズします。

## 必要なもの

- Python 3.8 以上（追加パッケージ不要）
- git（ブランチ・コミットの転送に使用）
- GitHub トークン：Fine-grained token なら対象リポジトリの **Pull requests: Read and write**、**Contents: Read and write**、**Issues: Read and write**
- Backlog API キー：個人設定 → API で発行
- 両リポジトリへの git push 権限（HTTPS なら Git 資格情報マネージャー、または SSH 鍵）

## セットアップ

```bat
cd F:\work\pr_migrate
copy config.example.json config.json
copy .env.example .env
rem config.json と .env を編集
python pr_migrate.py check
```

設定ファイルでは `a` と `b` に 2 つのリポジトリを書き、それぞれ `label` を付けます（省略時は Backlog = `BL`、GitHub = `GH`）。
旧バージョンの `source` / `target` の書き方もそのまま使え、`source` が a、`target` が b になります。

## 使い方

```bat
rem 両リポジトリの PR と同期状況
python pr_migrate.py list

rem まずは dry-run で内容を確認（書き込み・push は行いません）
python pr_migrate.py sync --dry-run

rem 1 件だけ試す（ラベル:番号）
python pr_migrate.py sync --pr GH:12

rem 同期（未同期の PR はミラーを作成、同期中の PR は差分を反映）
python pr_migrate.py sync

rem 新しいミラーは作らず、既存の対応だけ同期
python pr_migrate.py sync --no-create

rem 5 分ごとに同期し続ける
python pr_migrate.py sync --watch 300
```

`migrate` は `sync` と同じ動作です（旧コマンド名）。

主なオプション：

| オプション | 説明 |
|---|---|
| `-c FILE` | 設定ファイル（既定 `config.json`）。リポジトリの組ごとに設定ファイルを分けられます |
| `--pr LABEL:N ...` | 対象 PR を指定（例 `BL:3 GH:12`。`a:3` / `b:12` も可） |
| `--state open/closed/merged/all` | 新しくミラーを作る PR の状態（既定 all） |
| `--since 2024-01-01` | この日以降に作成された PR のみ新規作成 |
| `--limit N` | 新規作成する最大件数 |
| `--no-create` | 新しいミラー PR を作らない |
| `--dry-run` | 実行内容の表示のみ |
| `--no-push` | ブランチ転送をしない |
| `--force-push` | head ブランチが両側で別々に進んだとき、同期元を優先して強制更新 |
| `--no-comments` | コメントを同期しない |
| `--debug` | 詳細ログ |

主な設定（`options`）：

| 設定 | 既定 | 説明 |
|---|---|---|
| `directions` | `both` | 新しいミラーを作る向き。`a_to_b` / `b_to_a` で片方向だけにできます（コメント・クローズの同期は常に双方向） |
| `title_label_format` | `"[{label}] "` | ミラー PR のタイトル先頭に付ける文字列 |
| `closed_pr_strategy` | `skip` | 既にクローズ済みの PR の扱い（`skip` / `snapshot` / `as-is`） |
| `sync_branches_both_ways` | `true` | ミラー側の head に push されたコミットを同期元に戻す |
| `sync_state` | `true` | クローズ / マージ / 再オープンの同期 |

## 動作の仕組み

1. **ミラーかどうかの判定**：状態ファイルの対応表で判定します。対応表に無くても、タイトルが相手側のラベル
   （例 GitHub 上の `[BL] `）で始まる PR や、本文がツールの印 `⇄` で始まる PR はミラーとみなし、
   さらにミラーを作ること（往復コピー）はしません。
2. **ブランチ**：両リポジトリを `.work/` のベアリポジトリに取得し、PR の head コミットを相手側へ push します。
   コミット SHA がそのまま移るため差分・履歴は同一です。前回同期したコミットから片側だけ進んでいればそちらに合わせ、
   両側が別々に進んでいる場合は警告して何もしません（`--force-push` で同期元を優先）。
3. **コメント**：ツールが投稿したコメントは先頭に `⇄ [GH] 〇〇 のコメント（日時）` のような見出しが付きます。
   投稿者は API トークンのユーザーになるため、見出しで元の投稿者と同期元を示します。
   ツールが投稿したコメントは対応表と `⇄` の印で見分け、再度コピーしません。
4. **クローズ同期**：前回の実行時からの状態変化を見て、片方がクローズ / マージされたらもう片方をクローズします
   （マージ済みの場合も、もう片方は「マージ」ではなく「クローズ」になります）。
   ツールが閉じた PR は、相手側が再オープンされたときに再オープンします。
5. **状態ファイル**：`state/config.state.json` に PR とコメントの対応を保存します。**このファイルは消さないでください。**
   旧バージョン（片方向移行）の状態ファイルは初回実行時に自動で変換されます（移行元 = a、移行先 = b）。

## 注意点・制限

- **Backlog のクローズ**：上記のとおり API でクローズできないため、手動でクローズしてください。
  対象は `list` で「※要手動クローズ」と表示されます。Backlog にはクローズ済み PR のミラーは作りません。
- **通知**：両側にコメントが投稿されるため、ウォッチしている人に通知が飛びます。
  同期用のボットアカウントのトークンを使うことをおすすめします。
- **タイトル・本文**：同期元が正です。ミラー側で編集した内容は、同期元が次に変更されたときに上書きされます。
- **添付ファイル・画像**：元 URL のまま参照されます（非公開リポジトリだと相手側で表示できない場合があります）。
- **記法**：本文・コメントは変換しません。Backlog 記法のプロジェクトでは `text_format` を合わせてください（見出し部分のみ変換されます）。
- **レビュー承認**：承認・変更要求は「〇〇が承認しました」というコメントとして再現します（承認状態そのものは移せません）。
- **リアクション・レビュー依頼者・ラベル・マイルストーン・担当者（既定）** は同期しません。
- `.env`・`config.json`・`state/`・`.work/` は `.gitignore` 済みです。トークンをコミットしないよう注意してください。
